# 最全历史回测流水线 Skill

## 定位
系统已具备全部回测"零件"（向量化引擎 `backtest_real.py`、事件驱动引擎 `backtest/engine.py`、撮合 `backtest/broker.py`、指标 `backtest/metrics.py`、Walk-Forward、蒙特卡洛+历史情景、DSR、多策略对比）。本技能**不重写零件，只做增量**：
1. 一个统一编排器 `scripts/master_backtest.py`，把所有组件按标准顺序串成 13 个 Stage；
2. 新增缺失环节（数据质量审计、双引擎交叉验证、参数高原检测、多基准、成本敏感性、分段绩效、结果存档）；
3. 输出一份总报告 HTML 与七道"准入门"判定——**全绿才允许进入模拟盘（衔接 paper-trading-graduation 技能）**。

## 铁律（必须遵守）
- 信号当日决策、**次日开盘价成交**；禁止任何未来函数；财报数据在**披露日之后**才可用。
- 所有收益数字必须含成本（佣金万2.5、最低5元、印花税千1卖出、过户费、滑点、冲击成本），并同时给出"零成本"对照。
- 每个 Stage 独立 try/except：单个 Stage 失败记录状态、不阻断其余 Stage；**禁止在数据缺失时输出"全部正常"**。
- 全部复用现有模块，不新建第二套指标/撮合/数据加载代码。

## 各 Stage 规格

### Stage 0 · 数据质量审计（新增，建议文件 `backtest/data_audit.py`）
输出每只股票与全库的审计清单：
1. **交易日完整性**：以 `utils/trading_calendar.py` 交易日历为基准，列出缺失交易日；
2. **单股检查**：数据长度、停牌日（零成交）、OHLC 一致性（high≥low、high≥open/close≥low）、异常跳空（|涨跌|超板块涨跌幅限制但非涨跌停）、重复日期、负价格/负成交量；
3. **除权除息**：复权方式（前复权）与除权缺口标记，确认回测用复权价、成交用真实价；
4. **幸存者偏差声明**：股票池是否含已退市/已ST摘牌标的；若不含，明确标注"结果存在幸存者偏差，收益可能高估"；
5. 结论分级：阻断级错误（数据不可用）/ 警告级（可继续但需声明）/ 通过。

### Stage 1 · 单标的回测
复用 `backtest_real.backtest_stock_v5(df, code, info)`，逐只跑全区间，输出每只的交易明细、胜率、收益、MFE/MAE；汇总横截面排名。

### Stage 2 · 等权组合回测
复用 `backtest/engine.py` 的 `BacktestEngineV2`（默认 10 只等权），输出每日净值、成交、完整绩效（`metrics.generate_performance_report`）。

### Stage 3 · 全量股票池回测
复用 `run_full_backtest.py` 的加载与运行逻辑（全池标的，分批/滚动选股），输出全池层面的组合绩效与覆盖标的数。

### Stage 4 · 双引擎交叉验证（新增）
同一策略、同一区间、同一股票集合，分别用向量化引擎（Stage 1 汇总口径）与事件驱动引擎（Stage 2）计算：
- 对比总收益、夏普、胜率、交易笔数；
- 准入门：总收益差异 < 3%、夏普差异 < 0.3；超阈值说明两引擎逻辑不一致，必须排查（常见：成交价口径、停牌处理、涨跌停成交）。

### Stage 5 · 参数网格 + 高原检测
1. 网格**只扫 2–4 个核心参数**（如初始止损、信号质量门槛、ATR 倍数），全组合逐一回测，**记录每个 trial 的夏普（trial 总数供 Stage 8 DSR）**；
2. **参数高原检测（新增）**：对最优点的全部相邻参数（±1 档），若绩效平均退化 < 15% 判为"高原（稳健）"；若邻域急剧恶化（>30%）判为"孤点（过拟合）"；
3. 输出参数热力图（二维切片）与高原/孤点判定。

### Stage 6 · Walk-Forward
复用 `walk_forward.py`（默认训练 200 天/验证 60 天、最多 10 窗），输出各窗样本外夏普、参数稳定性、过拟合比率与综合判定。

### Stage 7 · 蒙特卡洛 + 历史情景压力
1. 复用 `monte_carlo.py`：交易顺序随机化（无放回 permutation），输出收益/最大回撤/夏普分布、破产概率（腰斩）、预期最大连亏、极端场景；
2. 复用历史情景库（2015股灾、2018贸易战、2020疫情、2022暴跌、2024微盘股崩），输出各情景下模拟收益、最大回撤、是否存活；
3. **新增日度 block bootstrap**：对日收益序列按 5–10 日块重采样生成净值路径（保留波动聚集），输出 95% 回撤与收益置信区间，与逐笔随机化结果交叉印证。

### Stage 8 · Deflated Sharpe + PBO
1. 复用 `deflated_sharpe.py`：以 Stage 5 真实 trial 数为多重检验次数，输出 DSR、预期最大夏普、p 值、haircut；
2. 可选：PBO（CSCV 组合对称交叉验证，过拟合概率），PBO > 0.5 判为过拟合；若实现成本高，可标注为后续增强，不阻断。

### Stage 9 · 多基准对比（新增）
基准至少含：沪深300（000300）、中证500（000905）、中证1000（000852）、中证2000（932000）、创业板指（399006）。
- 输出策略 vs 各基准的累计收益、年化、Beta、Alpha、信息比率、跟踪误差；
- 基准数据通过现有数据层统一获取、口径一致。

### Stage 10 · 成本敏感性（新增）
四档场景同策略回测：零成本 / 当前成本 / 成本×2（佣金印花税加倍）/ 滑点×3；
- 输出各档夏普与年化，计算"成本脆弱性"（成本×2 后夏普退化幅度）；
- 准入门：成本×2 后夏普退化 < 30%，否则策略依赖低换手/低滑点假设，实盘风险高。

### Stage 11 · 分段绩效（新增）
1. 自然年分段：每年收益、夏普、胜率、最大回撤；
2. 市场环境分段：复用 `strategy/market_regime.py` 判定 BULL/BEAR/RANGE，分环境统计（BEAR 段必须不出现大幅亏损，验证风控）；
3. 历史窗口：在 Stage 7 五个历史情景的真实日期窗口内回放策略实际表现（有数据的区间，如 2020/2022/2024），与情景模拟对照。

### Stage 12 · 因子分层回测
复用 `factors/` 与 factor-research 口径：对核心因子按月分 5 组，输出分层年化、多空收益、换手率、行业暴露，验证单调性；数据不足静默降级。

### Stage 13 · 存档 + 总报告
1. **结果存档（新增）**：每次运行写入存档（建议 SQLite 表 `backtest_runs` 或 JSONL）：run_id、git commit hash、时间、区间、资金、参数版本、全部核心指标、各 Stage 状态、耗时；
2. **基线 diff**：自动对比上一次存档（或指定基线），核心指标变化超阈值（如夏普±0.3、年化±5pct）标红，复用 `scripts/regression_replay.py`；
3. **总报告 HTML（新增，建议 `backtest/master_report.py`）**：单文件、红涨绿跌专业研报质感，结构：
   - 封面：七道门总览（红/黄/绿）与一句话结论；
   - 数据质量审计；净值曲线（策略 vs 多基准）+ 回撤；月度收益热力图；
   - 参数热力图与高原判定；Walk-Forward 各窗；蒙特卡洛分布图；历史情景卡片；
   - DSR/PBO；成本敏感性；分段绩效；因子分层；
   - 附录：口径、假设、已知限制（幸存者偏差/数据区间/退市股）、生成时间与 commit。

## 七道准入门（全部绿 → 允许进入模拟盘 paper）
| 门 | 判定标准（默认值，可在 config 覆盖） |
|---|---|
| G1 数据质量 | 无阻断级数据错误，警告项已在报告声明 |
| G2 样本外 | Walk-Forward 样本外平均夏普 > 0.8 |
| G3 DSR | DSR > 0.95（PBO < 0.5，若实现） |
| G4 成本稳健 | 成本×2 后夏普退化 < 30% |
| G5 参数高原 | 最优参数邻域绩效退化 < 15%，非孤点 |
| G6 压力存活 | 五个历史情景模拟均"存活"（资金不腰斩），BEAR 分段无大幅亏损 |
| G7 双引擎一致 | 两引擎总收益差 < 3%、夏普差 < 0.3 |

一门红 → 不进入模拟盘，报告列出具体问题与修复建议；黄 → 可进入但需在模拟盘重点观察。

## 实施原则
1. 编排器支持 CLI：`python scripts/master_backtest.py --stages 0,1,2`（可只跑部分 Stage）、`--quick`（小样本快速验证）、`--baseline <run_id>`；
2. 性能：quick 模式 < 1 分钟；全量流水线目标 < 30 分钟，慢 Stage 打印进度；
3. 向后兼容：不改现有策略逻辑与接口，新增配置在 config.py 分段集中管理；
4. 所有新增模块可独立测试，随附 `tests/test_master_backtest.py`。
