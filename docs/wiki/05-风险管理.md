# 05 - 风险管理

> 最后同步日期: 2026-07-28 | 对应代码版本: 操盘密码 V9.0（文档版本 V3.2）

> 本篇介绍操盘密码系统的风控体系。所有买卖指令必须先过风控，违规直接拦截，从代码层面管住手。

> **新手阅读建议**：风险管理是整个系统中**最重要的部分**，没有之一。
> 打个比方：如果炒股是开车，那风控就是"安全带+刹车+限速器"。
> 没有风控的炒股=不系安全带开180码，一次事故就够你"爆仓"（资金全部亏光）。
> 本系统的风控理念是：**先求不亏，再求赚钱**。每笔交易最多亏总资金的2%，
> 即使连续亏5笔也只亏10%，还有翻本的机会。但没有风控的话，一次全仓涨停板就能亏20%。
>
> 本篇涉及的系统模块：
> - 17道风控关卡 → `risk/risk_control.py`（UnifiedRiskEngine）
> - 仓位计算 → `strategy/position.py` + `position/kelly.py` + `position/vol_target.py`
> - 大盘状态检测 → `strategy/market_regime.py`
> - 蒙特卡洛压力测试 → `backtest/monte_carlo.py`
> - 持仓巡检 → `strategy/portfolio_analyzer.py`

## 一、风控关卡链（17道关卡）

> **打个比方**：17道关卡就像机场安检。你要登机（买入股票），必须过身份验证、行李扫描、液体检查等17个环节，
> 任何一个不通过就不让你上飞机。本系统也一样：每笔买入必须通过17道检查，
> 任何一道说"不行"就立即拦截——**不是警告你，而是直接不让你买**。

系统核心风控引擎 `UnifiedRiskEngine`（位于 `risk/risk_control.py`）采用**单例模式**，保证全局状态一致。每一笔买入信号必须依次通过以下关卡，任何一道不通过即被拦截：

| 关卡 | 名称 | 含义 | 系统参数 |
|------|------|------|----------|
| 关卡-1 | 盘中风险标记 | 盘中急跌触发暂停标记时，拒绝所有新买入 | `intraday_pause` |
| 关卡-0.5 | **策略失效检测** | 滚动20笔胜率<30%禁止买入；期望<0%全面熔断；降级时仓位×0.5 | `StrategyFailureDetector` |
| 关卡0 | 满仓禁止加仓 | 仓位≥90%绝对禁止买入；仓位≥80%禁止新开仓 | `full_position_threshold=0.90` |
| 关卡0.8 | **渐进加仓恢复** | 深亏后分3档恢复：30%→45%→60%，禁止一次性满仓 | `RiskStateManager.get_recovery_position_cap()` |
| 关卡0.9 | **MarketRegime动态上限** | 熊市→30% / 震荡→60% / 牛市→90%，缓存过期(>2天)自动失效 | `RiskStateManager.get_market_position_cap()` |
| 关卡0.5 | 股票池外拦截 | 不在核心池/观察池中的标的禁止买入 | `allowed_pool` |
| 关卡1 | 暂停期检查 | 连续亏损触发暂停后，在解禁日期前禁止开仓 | 状态文件持久化 |
| 关卡2 | 冷却期检查 | 卖出后N天内禁止重新买入同一标的 | `cool_down_days=2` |
| 关卡3 | 日开仓次数 | 每日最多开仓2笔 | `max_daily_opens=2` |
| 关卡4 | 连续亏损熔断 | 连亏2笔→当日禁止；连亏3笔→暂停3天 | `consecutive_loss_today=2` |
| 关卡5 | 时间红线 | 开盘前30分钟和收盘前30分钟禁止新开仓 | `NO_TRADE_MORNING/AFTERNOON` |
| 关卡6 | 日度亏损熔断 | 日亏≥2%只卖不买(L1)；日亏≥3%禁止开仓(L2) | `daily_loss_limit=0.02/0.03` |
| 关卡6.5 | **月度回撤硬限制** | 本月回撤≥5%时禁止新开仓（防守优先） | `monthly_drawdown_limit=0.05` |
| 关卡7 | 周度亏损熔断 | 周亏≥8%强制休息 | `weekly_loss_limit=0.08` |
| 关卡8 | 持仓数量限制 | 最多持有7只股票 | `max_holdings=7` |
| 关卡9 | 浮亏加仓拦截 | 持仓浮亏时绝对禁止加仓（铁律） | `block_add_on_loss=True` |
| 关卡10 | 个股仓位上限 | 龙头≤15%，弹性≤8%，ETF≤20% | `stock_max_ratio=0.15` |
| 关卡11 | 赛道仓位上限 | 同一赛道总仓位≤40% | `sector_max_ratio=0.40` |
| 关卡12 | 总仓位上限 | 按行情强度×波动率缩放×盘中风险动态调整 | 强势90%/震荡80%/弱势30% |
| 关卡13 | 现金安全垫 | 任何时刻保留≥10%现金 | `min_cash_ratio=0.10` |
| 关卡14 | **单笔风险硬钳位** | 单笔最大亏损≤总资金2%，超限**强制缩股**（非仅警告） | `max_single_loss_ratio=0.02` |

> **本系统应用**：`UnifiedRiskEngine._do_check()` 方法按顺序执行关卡-1到关卡14，每道关卡返回拦截结果时立即终止后续检查。风控状态（连续亏损、冷却期、月度基准等）通过 `output/risk_state.json` 文件持久化，重启系统后状态不丢失。
>
> **V7.1新增关卡说明**：
> - **关卡-0.5 策略失效检测**：`StrategyFailureDetector` 基于滚动20笔交易胜率判定三级状态（normal/degrade/pause/breaker），degrade时仓位缩放0.5，pause/breaker时完全禁止买入。恢复后前5笔仓位减半（试探性恢复）。
> - **关卡0.8 渐进加仓**：深亏（月度回撤>15%）后仓位上限30%；本月盈亏持平后升至45%；连续2周盈利后升至60%；完全恢复后解除限制。
> - **关卡0.9 MarketRegime**：读取 `output/market_regime_state.json` 缓存（每日16:15由scheduler更新），BEAR市仓位上限30%，RANGE 60%，BULL 90%。缓存超过2天自动失效。
> - **关卡6.5 月度回撤**：每月1日Walk-Forward任务重置 `monthly_start_capital` 基准，月内回撤≥5%时禁止新开仓。
> - **关卡14 强制缩股**：超限时不再仅发出警告，而是自动计算安全股数 `safe_shares = (总资金×2%) / (买入价-止损价)` 并替换原始股数。

### 数值示例

假设总资金 71.4万元，想买入海康威视（现价35元）1000股：

- **关卡10**：35×1000 = 35,000元，占比 35000/714324 = 4.9% < 15% ✅ 通过
- **关卡12**：如果当前持仓已占60%，加仓后达64.9%，震荡行情上限80% ✅ 通过
- **关卡13**：剩余现金 = 714324 - 已持仓 - 35000，需≥71432元 ✅/❌ 看具体情况

## 二、止损策略

> **打个比方**：止损就像"火灾逃生通道"。你住酒店时第一件事是看安全出口在哪，
> 买股票时第一件事就是设止损价。不是"觉得会跌才设"，而是"万一跌了知道在哪跑"。
> **没有止损=没有逃生通道**，一旦着火（暴跌）就只能等死。
> 举个例子：10元买入100股，止损设9元。如果跌到9元，卖出亏100元（10%）。
> 但如果不设止损，可能一路跌到5元，亏500元（50%）——要翻倍才能回本！

### 2.1 初始止损

买入时即设定止损价，系统提供两种方式：

**方式一：固定百分比止损**

```
止损价 = 买入价 × (1 - 止损比例)
```

- 龙头股：止损比例 = 10%（`INITIAL_STOP_LOSS_PCT = 0.10`）
- 弹性股：止损比例 = 12%

> **举例**：买入海康威视 35.287元，止损价 = 35.287 × 0.90 = 31.758元

**方式二：ATR自适应止损（V8.3新增）**

```
基础止损 = 现价 - ATR × 倍数（默认2.0）
保底止损 = 现价 × (1 - 5%)      ← 防止止损太远
极限止损 = 现价 × (1 - 15%)      ← 防止止损太近
最终止损 = max(基础止损, 保底止损)，且 ≤ 极限止损
```

> **本系统应用**：`strategy/position.py` 的 `calc_adaptive_stop_loss()` 函数实现ATR自适应止损。当ATR数据不可用时，自动回退到固定百分比止损。
>
> **举例**：某股现价100元，20日ATR=3.5元
> - 基础止损 = 100 - 3.5×2.0 = 93.0元（跌幅7%）
> - 保底止损 = 100 × 0.95 = 95.0元
> - 最终止损 = max(93.0, 95.0) = 95.0元

### 2.2 移动止损（追踪止损）

持仓浮盈后，止损价跟随上移，锁定已有利润：

| 浮盈区间 | 止损策略 | ATR移动止损逻辑 |
|----------|----------|-----------------|
| < 3% | 维持初始止损（成本价保本） | `trailing_stop = cost_price` |
| 3%~15% | 止损上移到成本价+1% | `trailing_stop = highest × (1 - ATR_ratio × 1.5)` |
| 15%~30% | 止损锁定盈利12% | `trailing_stop = highest × (1 - ATR_ratio × 1.0)` |
| > 30% | 止损锁定盈利22% | `trailing_stop = highest × (1 - ATR_ratio × 0.7)` |

> **本系统应用**：`strategy/position.py` 的 `calc_trailing_stop()` 函数实现连续移动止损，浮盈越多止损越紧。

### 2.3 时间止损

持仓超过20个交易日（4周），如果浮盈不足5%，系统**强制生成清仓单**以提高资金效率。

```
条件: 持仓天数 > MAX_HOLD_DAYS(20) AND 浮盈 < 5%
操作: 生成次日09:30强制离场条件单
```

> **本系统应用**：
> - `config.py` 中 `MAX_HOLD_DAYS = 20`，`TIME_STOP_PROFIT = 0.05`
> - `daily_orders.py`：读取 `holdings.json` 的 `buy_date` 字段计算持仓天数，超期且浮盈<5%时生成★★★必挂清仓单
> - `portfolio_analyzer.py` 规则4：时间止损清仓建议（持仓>20天且浮盈<5%→全量清仓）
>
> **设计背景**：科创50持仓409天浮亏-47.5%、豪威集团435天浮亏-12.4%，时间止损从未生效导致资金长期锁死。修复后该规则在条件单生成和组合分析两个层面同时生效。

### 2.4 止损/止盈触发价格规范

| 场景 | 触发价 | 说明 |
|------|--------|------|
| 盘中条件单止损 | **盘中最低价(low)** | 实盘条件单是盘中实时触发，非收盘价 |
| 回测止损判定 | **盘中最低价(low)** | `backtest_real.py` / `backtest_optimizer.py` 统一用 `low <= stop_price` |
| 回落止盈回撤 | **盘中最低价(low)** | 从最高价到最低价的回撤计算，模拟实盘触发 |
| 移动止盈回撤阈值 | **7%**（原10%） | `caopan_signal.py` 中 `pullback_from_high > 0.07` |

## 四、仓位管理方法

### 4.1 风险预算法（2%法则）

核心思想：**单笔最大亏损不超过总资金的2%**，据此反算可买股数。

```
最大亏损金额 = 总资金 × 2%
每股风险 = 买入价 - 止损价
最大股数 = 最大亏损金额 / 每股风险（向下取整到100股）
```

> **举例**：总资金71.4万，买入价100元，止损价90元
> - 最大亏损 = 714,324 × 2% = 14,286元
> - 每股风险 = 100 - 90 = 10元
> - 最大股数 = 14,286 / 10 = 1,428股 → 取整 1,400股
> - 买入金额 = 1,400 × 100 = 140,000元（占比19.6%）

### 4.2 凯利公式（Half Kelly）

凯利公式计算最优仓位比例：

```
f* = (b × p - q) / b
其中: b = 盈亏比, p = 胜率, q = 1 - p
系统使用半凯利（f* × 0.5），更保守
```

> **本系统应用**：`strategy/position.py` 的 `calc_first_batch()` 会查询 `trade_journal.db` 获取该股票的历史胜率和盈亏比（至少5笔交易），计算半凯利仓位。无历史数据时使用默认值：胜率45%、盈亏比2.0。
>
> **举例**：某股历史胜率50%，盈亏比2.0
> - f* = (2.0 × 0.50 - 0.50) / 2.0 = 0.25（25%）
> - 半凯利 = 25% × 0.5 = 12.5%
> - 可买金额 = 714,324 × 12.5% = 89,290元

### 4.3 波动率目标（Vol Target）

基于组合波动率目标动态调整总仓位，保持风险暴露恒定：

```
目标仓位比例 = 目标波动率 / 预测波动率 × 基准仓位
实际仓位 = min(目标仓位, 硬上限) × 信号置信度
```

> **本系统应用**：`position/vol_target.py` 的 `VolTargetManager` 实现：
> - 目标年化波动率 = 15%（`target_vol=0.15`）
> - 使用EWMA方法预测波动率（衰减因子0.94，RiskMetrics标准）
> - 波动率regime分5档：极低(<12%)、低(12-20%)、正常(20-30%)、高(30-45%)、极端(>45%)
> - 大盘弱势时额外打7折
>
> **举例**：目标波动率15%，当前组合预测波动率25%
> - scale = 15% / 25% = 0.60
> - 原始计划1000股 → 调整为600股

### 4.4 分批建仓

系统采用两批建仓策略：

| 批次 | 比例 | 条件 |
|------|------|------|
| 第一批（试仓） | 40% | 信号触发即买入 |
| 第二批（加仓） | 60% | 第一批浮盈≥3%后才允许 |

> **本系统应用**：`strategy/position.py` 的 `calc_first_batch()` 和 `calc_second_batch()` 实现。第一批还会叠加Kelly约束和ATR波动率调整，取最小值。

## 五、VaR / CVaR 概念

> **打个比方**：VaR就像天气预报里的"极端天气预警"。
> "95%VaR=3.29%"的意思是：100天里有95天亏损不会超过3.29%，但有5天可能超过。
> CVaR则进一步告诉你："那5天里平均会亏多少"——通常是VaR的1.5-2倍。
> 通俗来说：VaR="正常情况下的最坏结果"，CVaR="真正倒霉时的平均损失"。

### VaR（Value at Risk，在险价值）

**含义**：在给定置信度下，未来一段时间内可能遭受的最大损失。

```
95% VaR = 1.645 × 组合标准差 × √持有天数
```

> **举例**：组合日波动率2%，95%置信度下：
> - 1日VaR = 1.645 × 2% = 3.29%
> - 含义：有95%的把握，明天亏损不超过3.29%

### CVaR（Conditional VaR，条件在险价值）

**含义**：当亏损超过VaR时，平均会亏多少。CVaR比VaR更保守，关注尾部风险。

> **本系统应用**：`config.py` 中 `RISK_CONFIG["var_confidence"] = 0.95`，组合风险管理模块计算VaR和CVaR用于评估持仓集中度风险。

## 六、蒙特卡洛压力测试

> **打个比方**：历史回测只展示了"一种可能的经历"，但实际交易中亏损的顺序是随机的。
> 蒙特卡洛就像"平行宇宙模拟器"：把你的交易记录打乱1000次，看看不同顺序下结果如何。
> 也许你历史回测很顺利，但如果前5笔恰好都是亏损的呢？蒙特卡洛就是测试这种"最坏运气"。

### 原理

历史回测只展示了一条路径，但交易顺序是随机的。蒙特卡洛通过**重采样**生成数千条可能路径，揭示风险分布。

### 系统实现

> **本系统应用**：`backtest/monte_carlo.py` 的 `MonteCarloStressTest` 类：
> - 默认模拟1000次（`n_simulations=1000`）
> - 每次随机打乱历史交易顺序（无放回排列），模拟资金曲线
> - 计算最大回撤、连续亏损、夏普比率的分布

### 输出指标解读

| 指标 | 含义 | 示例 |
|------|------|------|
| `return_distribution.p5` | 5%分位收益（悲观情况） | -8%：最差的5%情况下亏损超8% |
| `max_drawdown_distribution.p95` | 95%分位最大回撤 | 25%：95%的情况下回撤不超25% |
| `ruin_probability` | 破产概率（资金腰斩） | 2%：有2%的概率资金跌破50% |
| `consecutive_loss.p95` | 95%分位最大连亏 | 5笔：95%的情况下连亏不超5笔 |

### 极端场景测试

系统自动模拟3类极端场景：

| 场景 | 说明 |
|------|------|
| 连续N笔止损 | 连续3/5/7笔平均亏损 |
| 单日跌停 | 历史最大单日跌幅 |
| 极端连亏 | 最差10%的交易连续出现5笔 |

> **数值示例**：假设历史50笔交易，平均亏损-5%
> - 连续3笔止损：资金缩水至 (1-0.05)³ = 85.7%，亏损14.3%
> - 连续5笔止损：资金缩水至 (1-0.05)⁵ = 77.4%，亏损22.6%
> - 单日跌停：假设最差-9.8%，一天亏9.8%

### 结论性陈述

系统自动生成可读结论：
```
基于50笔历史交易的1000次蒙特卡洛模拟:
  • 95%置信度下最大回撤不超过 22.3%
  • 收益区间: [-8.5%, +35.2%] (5%~95%分位)
  • 破产概率(资金腰斩): 1.20%
  • 预期最大连亏: 4笔 (95%分位: 6笔)
```

## 七、持仓健康度巡检

系统对每只持仓进行四级风险分类：

| 等级 | 条件 | 处置建议 |
|------|------|----------|
| 🟢 健康 | 多头趋势 + 浮盈 + 止损上移 | 持有，止损上移 |
| 🟡 关注 | 多头+浮亏 或 非多头+浮盈 | 持有+带好止损 |
| 🟠 预警 | 空头趋势 + 浮亏<15% | 反弹减仓（设14:50条件单） |
| 🔴 危险 | 浮亏>15% 或 跌破MA60且亏>10% | 无条件清仓 |

> **本系统应用**：`UnifiedRiskEngine.inspect_holdings()` 方法遍历所有持仓，按紧急程度排序输出，并为仓位超标的标的计算具体减仓方案。

## 八、总仓位动态上限（双层联动）

系统总仓位上限由**两层机制**共同约束，取更严格的一方：

### 8.1 均线动态上限（关卡12原有）

| 市场状态 | 条件 | 总仓位上限 |
|----------|------|------------|
| 强势 | 指数 > MA20 > MA60 | 80%~90% |
| 震荡 | 指数跌破MA20 | 50%~80% |
| 弱势 | 指数跌破MA60 | 30% |

> `risk_control.py` 的 `_get_dynamic_total_limit()` 方法。盘中系统性风险标记会进一步将上限强制降至30%。

### 8.2 MarketRegimeDetector联动（关卡0.9新增）

| 市场状态 | 检测方式 | 仓位上限 | 策略建议 |
|----------|----------|----------|----------|
| BULL（牛市） | 综合评分>0.3 | **90%** | 趋势跟踪 |
| RANGE（震荡） | 评分-0.3~0.3 | **60%** | 高抛低吸 |
| BEAR（熊市） | 综合评分<-0.3 | **30%** | 防守为主 |

> **数据流**：`strategy/market_regime.py` 的 `MarketRegimeDetector.detect()` 基于沪深300日线计算5维评分（趋势35%+量能20%+动量15%+波动率15%+市场宽度15%）→ 每日16:15由 `scheduler.py` 的 `_cache_market_regime_state()` 写入 `output/market_regime_state.json` → 买入时 `RiskStateManager.get_market_position_cap()` 读取缓存并约束仓位。
>
> **容错**：缓存文件不存在或超过2天未更新时，自动返回1.0（不限制），避免数据过期误拦。

## 十、策略失效检测器（StrategyFailureDetector）

基于滚动窗口胜率/期望收益的**三级熔断机制**，位于 `risk/risk_control.py`：

| 等级 | 触发条件 | 仓位影响 | 买入权限 |
|------|----------|----------|----------|
| normal | 滚动20笔胜率≥40% | scale=1.0 | 允许 |
| degrade | 滚动20笔胜率<40% | scale=0.5（仓位减半） | 允许（缩股） |
| pause | 滚动20笔胜率<30% | scale=0.0 | **禁止买入** |
| breaker | 滚动20笔期望<0% | scale=0.0 | **全面暂停** |

**恢复机制**：从pause/breaker恢复到normal后，前5笔交易仓位减半（`RECOVERY_TRADES=5`，试探性恢复）。

**状态持久化**：`output/strategy_failure_state.json`，记录 `trade_history`（最近20笔）、`current_level`、`trades_since_recovery`。

**联动点**：
- `UnifiedRiskEngine._do_check()` 关卡-0.5：读取 `check_buy_allowed()` 决定是否拦截/缩股
- `PositionSizer.calc_positions()`：读取 `get_status()` 的 `position_scale` 统一缩放所有建议仓位

## 本节小结

| 核心要点 | 一句话总结 |
|---------|------------|
| 17道关卡 | 每笔买入必须过17道安检，任何一道不过就拦截 |
| 止损 | 买入时就设好"逃生价"，跌到就无条件卖 |
| 2%法则 | 单笔最大亏损≤总资金2%，据此反算买多少股 |
| 移动止损 | 赚得越多止损越紧，锁住利润不回吐 |
| 时间止损 | 持仓20天还不涨就走人，不耗时间 |
| VaR | "95%的情况下最多亏X%"的风险预警 |
| 蒙特卡洛 | 模拟1000种运气，看最坏情况能否承受 |
| 策略熔断 | 连亏时自动"强制休息"，防止情绪化交易 |

**新手记住三条铁律**：
1. **永远先设止损再买入**——10元买入，止损9元，跌到就卖，不抱幻想
2. **单笔亏损不超过总资金2%**——71.4万的2%=14286元，这是你每笔能承受的最大亏损
3. **连亏时不要报复性加仓**——系统会自动熔断禁止你买，这是保护你

## 常见疑问FAQ

**Q1：为什么止损设10%而不是5%或20%？**

A：这是回测验证的结果：
- 5%太紧：A股每天正常波动就有3-5%，设5%会被"正常波动"频繁触发，反复割肉
- 20%太宽：亏20%需要涨25%才能回本，心理压力大且资金效率低
- 10%是平衡点：既给正常波动留了空间，又不至于亏太深
- 本系统还用ATR自适应：波动大的股票止损宽一点，波动小的窄一点

**Q2："浮亏时禁止加仓"是为什么？我觉得跌了应该补仓拉低成本啊？**

A：这是新手最常见的致命错误。打个比方：
- 你10元买了某股，跌到8元（亏20%），你觉得"便宜了"又买一批
- 结果它继续跌到5元，你现在两批都亏，总亏损更大
- 正确做法：跌了说明你判断错了，应该止损走人，而不是"越跌越买"
- 本系统用代码强制禁止这种行为（关卡9），不给你"手痒"的机会

**Q3：17道关卡会不会太严了？导致错过很多机会？**

A：会错过一些机会，但这是故意的。量化交易的核心理念是：
- 市场上每天都有机会，错过今天还有明天
- 但资金亏光了就没有"明天"了
- 17道关卡拦截的是"高风险操作"，不是"所有操作"
- 在牛市（BULL）时，大部分关卡都会顺利通过，不会限制你
- 只有在熊市/连亏/满仓等危险情况下才会拦截

**Q4：什么是"熔断"？和股市熔断有什么关系？**

A：本系统的熔断借鉴了股市熔断的概念，但是针对你个人的：
- 股市熔断：大盘跌太多，全市场暂停交易
- 本系统熔断：你连亏太多，系统禁止你继续买入
- 具体规则：连亏2笔→当日禁止；连亏3笔→暂停3天；月度回撤≥5%→禁止新开仓
- 目的：防止你在情绪失控时"报复性交易"（想赶紧赚回来，结果越亏越多）

**Q5：蒙特卡洛测试的"破产概率2%"是什么意思？**

A：意思是：在1000次模拟中，有20次（2%）资金跌破了50%（腰斩）。
- 2%很低，说明策略风险可控
- 但如果破产概率>10%，说明策略太激进，需要降低仓位
- 本系统要求破产概率<5%才允许实盘运行
