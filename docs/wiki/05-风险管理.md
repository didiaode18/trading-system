# 05 - 风险管理

> 本篇介绍操盘密码系统的风控体系。所有买卖指令必须先过风控，违规直接拦截，从代码层面管住手。

---

## 一、风控关卡链（14道关卡）

系统核心风控引擎 `UnifiedRiskEngine`（位于 `risk/risk_control.py`）采用**单例模式**，保证全局状态一致。每一笔买入信号必须依次通过以下关卡，任何一道不通过即被拦截：

| 关卡 | 名称 | 含义 | 系统参数 |
|------|------|------|----------|
| 关卡-1 | 盘中风险标记 | 盘中急跌触发暂停标记时，拒绝所有新买入 | `intraday_pause` |
| 关卡0 | 满仓禁止加仓 | 仓位≥90%绝对禁止买入；仓位≥80%禁止新开仓 | `full_position_threshold=0.90` |
| 关卡0.5 | 股票池外拦截 | 不在核心池/观察池中的标的禁止买入 | `allowed_pool` |
| 关卡1 | 暂停期检查 | 连续亏损触发暂停后，在解禁日期前禁止开仓 | 状态文件持久化 |
| 关卡2 | 冷却期检查 | 卖出后N天内禁止重新买入同一标的 | `cool_down_days=2` |
| 关卡3 | 日开仓次数 | 每日最多开仓2笔 | `max_daily_opens=2` |
| 关卡4 | 连续亏损熔断 | 连亏2笔→当日禁止；连亏3笔→暂停3天 | `consecutive_loss_today=2` |
| 关卡5 | 时间红线 | 开盘前30分钟和收盘前30分钟禁止新开仓 | `NO_TRADE_MORNING/AFTERNOON` |
| 关卡6 | 日度亏损熔断 | 日亏≥2%只卖不买(L1)；日亏≥3%禁止开仓(L2) | `daily_loss_limit=0.02/0.03` |
| 关卡7 | 周度亏损熔断 | 周亏≥8%强制休息 | `weekly_loss_limit=0.08` |
| 关卡8 | 持仓数量限制 | 最多持有7只股票 | `max_holdings=7` |
| 关卡9 | 浮亏加仓拦截 | 持仓浮亏时绝对禁止加仓（铁律） | `block_add_on_loss=True` |
| 关卡10 | 个股仓位上限 | 龙头≤15%，弹性≤8%，ETF≤20% | `stock_max_ratio=0.15` |
| 关卡11 | 赛道仓位上限 | 同一赛道总仓位≤40% | `sector_max_ratio=0.40` |
| 关卡12 | 总仓位上限 | 按行情强度×波动率缩放×盘中风险动态调整 | 强势90%/震荡80%/弱势30% |
| 关卡13 | 现金安全垫 | 任何时刻保留≥10%现金 | `min_cash_ratio=0.10` |
| 关卡14 | 单笔亏损控制 | 单笔最大亏损≤总资金2% | `max_single_loss_ratio=0.02` |

> **本系统应用**：`UnifiedRiskEngine._do_check()` 方法按顺序执行关卡-1到关卡14，每道关卡返回拦截结果时立即终止后续检查。风控状态（连续亏损、冷却期等）通过 `output/risk_state.json` 文件持久化，重启系统后状态不丢失。

### 数值示例

假设总资金 71.4万元，想买入海康威视（现价35元）1000股：

- **关卡10**：35×1000 = 35,000元，占比 35000/714324 = 4.9% < 15% ✅ 通过
- **关卡12**：如果当前持仓已占60%，加仓后达64.9%，震荡行情上限80% ✅ 通过
- **关卡13**：剩余现金 = 714324 - 已持仓 - 35000，需≥71432元 ✅/❌ 看具体情况

## 二、止损策略

### 2.1 初始止损

买入时即设定止损价，系统提供两种方式：

**方式一：固定百分比止损**

```
止损价 = 买入价 × (1 - 止损比例)
```

- 龙头股：止损比例 = 10%（`INITIAL_STOP_LOSS_PCT = 0.10`）
- 弹性股：止损比例 = 12%

> **举例**：买入海康威视 35.287元，止损价 = 35.287 × 0.90 = 31.758元

**方式二：ATR自适应止损（V8.3新增）**

```
基础止损 = 现价 - ATR × 倍数（默认2.0）
保底止损 = 现价 × (1 - 5%)      ← 防止止损太远
极限止损 = 现价 × (1 - 15%)      ← 防止止损太近
最终止损 = max(基础止损, 保底止损)，且 ≤ 极限止损
```

> **本系统应用**：`strategy/position.py` 的 `calc_adaptive_stop_loss()` 函数实现ATR自适应止损。当ATR数据不可用时，自动回退到固定百分比止损。
>
> **举例**：某股现价100元，20日ATR=3.5元
> - 基础止损 = 100 - 3.5×2.0 = 93.0元（跌幅7%）
> - 保底止损 = 100 × 0.95 = 95.0元
> - 最终止损 = max(93.0, 95.0) = 95.0元

### 2.2 移动止损（追踪止损）

持仓浮盈后，止损价跟随上移，锁定已有利润：

| 浮盈区间 | 止损策略 | ATR移动止损逻辑 |
|----------|----------|-----------------|
| < 3% | 维持初始止损（成本价保本） | `trailing_stop = cost_price` |
| 3%~15% | 止损上移到成本价+1% | `trailing_stop = highest × (1 - ATR_ratio × 1.5)` |
| 15%~30% | 止损锁定盈利12% | `trailing_stop = highest × (1 - ATR_ratio × 1.0)` |
| > 30% | 止损锁定盈利22% | `trailing_stop = highest × (1 - ATR_ratio × 0.7)` |

> **本系统应用**：`strategy/position.py` 的 `calc_trailing_stop()` 函数实现连续移动止损，浮盈越多止损越紧。

### 2.3 时间止损

持仓超过20个交易日（4周），如果浮盈不足5%，系统建议卖出以提高资金效率。

```
条件: 持仓天数 > 20 AND 浮盈 < 5%
操作: 生成卖出信号
```

> **本系统应用**：`config.py` 中 `MAX_HOLD_DAYS = 20`，`TIME_STOP_PROFIT = 0.05`。

## 三、止盈策略

### 3.1 阶梯目标止盈

| 浮盈阈值 | 操作 |
|----------|------|
| 10% | 卖出1/3仓位 |
| 20% | 再卖出1/3仓位 |

### 3.2 回落止盈

从最高价回落一定比例时触发：

| 股票类型 | 回落阈值 |
|----------|----------|
| 龙头稳健 | 7% |
| 成长赛道 | 6% |
| 高弹性 | 5% |

> **本系统应用**：`daily_orders.py` 的条件单生成逻辑中，浮盈>15%的持仓自动生成"移动止盈"条件单，触发价 = 20日最高价 × 95%。

## 四、仓位管理方法

### 4.1 风险预算法（2%法则）

核心思想：**单笔最大亏损不超过总资金的2%**，据此反算可买股数。

```
最大亏损金额 = 总资金 × 2%
每股风险 = 买入价 - 止损价
最大股数 = 最大亏损金额 / 每股风险（向下取整到100股）
```

> **举例**：总资金71.4万，买入价100元，止损价90元
> - 最大亏损 = 714,324 × 2% = 14,286元
> - 每股风险 = 100 - 90 = 10元
> - 最大股数 = 14,286 / 10 = 1,428股 → 取整 1,400股
> - 买入金额 = 1,400 × 100 = 140,000元（占比19.6%）

### 4.2 凯利公式（Half Kelly）

凯利公式计算最优仓位比例：

```
f* = (b × p - q) / b
其中: b = 盈亏比, p = 胜率, q = 1 - p
系统使用半凯利（f* × 0.5），更保守
```

> **本系统应用**：`strategy/position.py` 的 `calc_first_batch()` 会查询 `trade_journal.db` 获取该股票的历史胜率和盈亏比（至少5笔交易），计算半凯利仓位。无历史数据时使用默认值：胜率45%、盈亏比2.0。
>
> **举例**：某股历史胜率50%，盈亏比2.0
> - f* = (2.0 × 0.50 - 0.50) / 2.0 = 0.25（25%）
> - 半凯利 = 25% × 0.5 = 12.5%
> - 可买金额 = 714,324 × 12.5% = 89,290元

### 4.3 波动率目标（Vol Target）

基于组合波动率目标动态调整总仓位，保持风险暴露恒定：

```
目标仓位比例 = 目标波动率 / 预测波动率 × 基准仓位
实际仓位 = min(目标仓位, 硬上限) × 信号置信度
```

> **本系统应用**：`position/vol_target.py` 的 `VolTargetManager` 实现：
> - 目标年化波动率 = 15%（`target_vol=0.15`）
> - 使用EWMA方法预测波动率（衰减因子0.94，RiskMetrics标准）
> - 波动率regime分5档：极低(<12%)、低(12-20%)、正常(20-30%)、高(30-45%)、极端(>45%)
> - 大盘弱势时额外打7折
>
> **举例**：目标波动率15%，当前组合预测波动率25%
> - scale = 15% / 25% = 0.60
> - 原始计划1000股 → 调整为600股

### 4.4 分批建仓

系统采用两批建仓策略：

| 批次 | 比例 | 条件 |
|------|------|------|
| 第一批（试仓） | 40% | 信号触发即买入 |
| 第二批（加仓） | 60% | 第一批浮盈≥3%后才允许 |

> **本系统应用**：`strategy/position.py` 的 `calc_first_batch()` 和 `calc_second_batch()` 实现。第一批还会叠加Kelly约束和ATR波动率调整，取最小值。

## 五、VaR / CVaR 概念

### VaR（Value at Risk，在险价值）

**含义**：在给定置信度下，未来一段时间内可能遭受的最大损失。

```
95% VaR = 1.645 × 组合标准差 × √持有天数
```

> **举例**：组合日波动率2%，95%置信度下：
> - 1日VaR = 1.645 × 2% = 3.29%
> - 含义：有95%的把握，明天亏损不超过3.29%

### CVaR（Conditional VaR，条件在险价值）

**含义**：当亏损超过VaR时，平均会亏多少。CVaR比VaR更保守，关注尾部风险。

> **本系统应用**：`config.py` 中 `RISK_CONFIG["var_confidence"] = 0.95`，组合风险管理模块计算VaR和CVaR用于评估持仓集中度风险。

## 六、蒙特卡洛压力测试

### 原理

历史回测只展示了一条路径，但交易顺序是随机的。蒙特卡洛通过**重采样**生成数千条可能路径，揭示风险分布。

### 系统实现

> **本系统应用**：`backtest/monte_carlo.py` 的 `MonteCarloStressTest` 类：
> - 默认模拟1000次（`n_simulations=1000`）
> - 每次随机打乱历史交易顺序（无放回排列），模拟资金曲线
> - 计算最大回撤、连续亏损、夏普比率的分布

### 输出指标解读

| 指标 | 含义 | 示例 |
|------|------|------|
| `return_distribution.p5` | 5%分位收益（悲观情况） | -8%：最差的5%情况下亏损超8% |
| `max_drawdown_distribution.p95` | 95%分位最大回撤 | 25%：95%的情况下回撤不超25% |
| `ruin_probability` | 破产概率（资金腰斩） | 2%：有2%的概率资金跌破50% |
| `consecutive_loss.p95` | 95%分位最大连亏 | 5笔：95%的情况下连亏不超5笔 |

### 极端场景测试

系统自动模拟3类极端场景：

| 场景 | 说明 |
|------|------|
| 连续N笔止损 | 连续3/5/7笔平均亏损 |
| 单日跌停 | 历史最大单日跌幅 |
| 极端连亏 | 最差10%的交易连续出现5笔 |

> **数值示例**：假设历史50笔交易，平均亏损-5%
> - 连续3笔止损：资金缩水至 (1-0.05)³ = 85.7%，亏损14.3%
> - 连续5笔止损：资金缩水至 (1-0.05)⁵ = 77.4%，亏损22.6%
> - 单日跌停：假设最差-9.8%，一天亏9.8%

### 结论性陈述

系统自动生成可读结论：
```
基于50笔历史交易的1000次蒙特卡洛模拟:
  • 95%置信度下最大回撤不超过 22.3%
  • 收益区间: [-8.5%, +35.2%] (5%~95%分位)
  • 破产概率(资金腰斩): 1.20%
  • 预期最大连亏: 4笔 (95%分位: 6笔)
```

## 七、持仓健康度巡检

系统对每只持仓进行四级风险分类：

| 等级 | 条件 | 处置建议 |
|------|------|----------|
| 🟢 健康 | 多头趋势 + 浮盈 + 止损上移 | 持有，止损上移 |
| 🟡 关注 | 多头+浮亏 或 非多头+浮盈 | 持有+带好止损 |
| 🟠 预警 | 空头趋势 + 浮亏<15% | 反弹减仓（设14:50条件单） |
| 🔴 危险 | 浮亏>15% 或 跌破MA60且亏>10% | 无条件清仓 |

> **本系统应用**：`UnifiedRiskEngine.inspect_holdings()` 方法遍历所有持仓，按紧急程度排序输出，并为仓位超标的标的计算具体减仓方案。

## 八、总仓位动态上限

系统总仓位上限与**大盘指数均线**绑定，自动适应市场强弱：

| 市场状态 | 条件 | 总仓位上限 |
|----------|------|------------|
| 强势 | 指数 > MA20 > MA60 | 80%~90% |
| 震荡 | 指数跌破MA20 | 50%~80% |
| 弱势 | 指数跌破MA60 | 30% |

> **本系统应用**：`risk_control.py` 的 `_get_dynamic_total_limit()` 方法。当 `index_price < index_ma60` 时返回30%，`index_price < index_ma20` 时返回50%，否则返回80%。此外，盘中系统性风险标记会进一步将上限强制降至30%。

## 九、风控状态持久化

系统通过 `output/risk_state.json` 文件记录以下状态：

| 字段 | 含义 |
|------|------|
| `consecutive_losses` | 连续亏损笔数 |
| `pause_until` | 暂停开仓截止日期 |
| `daily_open_count` | 今日已开仓次数 |
| `daily_pnl` | 当日已实现盈亏 |
| `weekly_pnl` | 本周已实现盈亏 |
| `sell_cooldown` | 各标的卖出冷却期 |
| `intraday_risk_flags` | 盘中风险标记 |

> 每日日期变更时，`daily_open_count` 和 `daily_pnl` 自动重置。盘中风险标记在15:30后自动过期清除。
