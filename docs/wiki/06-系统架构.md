# 06 - 系统架构

> 本篇基于实际代码描述操盘密码系统的模块关系、数据流转和调度时序。
> 系统版本：V9.0+V6.0 | 13个模块层 | 更新日期: 2026-08-31（CANSLIM V6.0选股引擎全面升级同步）

> **新手阅读建议**：本篇内容偏技术，如果你只想用系统炒股，可以先跳过本篇，直接看[第7篇：使用手册](./07-使用手册.md)。
> 但如果你想理解"系统是怎么工作的"，本篇会告诉你：
> - 系统由哪些"零件"组成（13个模块层）
> - 数据怎么流动（从原始行情→分析→信号→风控→报告）
> - 每天什么时间做什么事（调度时序）
>
> 打个比方：本系统就像一个"自动化餐厅"——
> 数据层=采购食材，因子层=切菜备料，策略层=大厨炒菜，风控层=食品安全检查，
> 输出层=装盘上桌，通知层=服务员上菜。每个环节各司其职，单向流动。

## 一、模块架构图（13层）

> **打个比方**：13个模块层就像一家公司的13个部门。
> 数据部（data/）负责采集信息，研发部（strategy/）负责分析决策，
> 风控部（risk/）负责审核把关，财务部（position/）负责资金分配，
> 客服部（notify/）负责发送报告。各部门单向协作，互不干扰。

### 模块间依赖关系（单向数据流）

> **通俗来说**：数据从下往上流，就像工厂流水线：原材料（数据）→加工（因子/策略）→质检（风控）→出货（报告）。
> 任何模块不会"回头"影响上游，这保证了系统的稳定性。

```
config.py ←── 所有模块（全局配置中心）
     │
     ├── data/ ←── strategy/ ←── risk/ ←── output/
     │                  │             │
     │                  └── position/ ←┘
     │
     ├── backtest/ ←── scheduler.py
     ├── ml/       ←── scheduler.py
     └── factors/  ←── scheduler.py
```

> **本系统应用**：`config.py` 作为全局默认配置中心，提供安全占位符（资金=0、邮箱=空、股票池=空）。用户私有数据（实际资金/邮箱/股票池）统一写在 `config_local.py`（已被 .gitignore 排除，不会提交到仓库）。启动时 `config.py` 末尾自动执行 `from config_local import *` 覆盖默认值。修改参数只需编辑 `config_local.py`。

## 三、调度时序图（每天自动执行的时间表）

> **打个比方**：调度器就像一个"自动闹钟"，每天按固定时间做固定的事。
> 你不需要手动操作，系统会自动在对应时间发邮件给你。
> 你只需要：早上看盘前报告→盘中看预警→晚上看综合报告→按条件单操作。

系统采用 **“4+1”报告体系**（4份定时报告 + 盘中预警）：

### 3.1 交易日时间线

```
08:30 ──── 盘前作战计划（scheduler.run_forecast_morning）
  │         内容: 大盘展望 + 持仓操作清单 + 关键价位 + 仓位建议
  │         邮件: [盘前作战计划] 日期 | N项操作
  │
09:25 ──── 竞价后选股（scheduler.run_morning_screener）
  │         内容: 全赛道选股扫描 + CANSLIM评分
  │         邮件: [选股推荐] N只入选
  │
09:30 ──── 盘中监控启动（后台线程）
  │         IntradayMonitor 每30秒轮询持仓实时行情
  │         触发条件: 急跌>3% / 大盘急跌>1.5% / 振幅>8%
  │         联动: 触发时设置 risk_state.intraday_risk_flags
  │
10:00 ──── 禁止新开仓时段开始
  │
13:30 ──── 禁止新开计划外标的
  │
14:30 ──── 禁止新开仓时段开始
  │
15:01 ──── 盘中监控停止
  │
15:30 ──── 盘后综合日报（scheduler.run_daily_task）
  │         内容: 数据更新 → 信号扫描 → 九大模块分析 → 综合日报
  │         附加: ML预测 + IC因子监控 + 预测验证回填
  │         邮件: [盘后综合日报] 日期 | 买N/卖N | 风险N分
  │
16:15 ──── 综合分析报告（scheduler.run_holdings_report_task）
  │         内容: 逐只持仓深度技术诊断 + 条件单 + 选股推荐
  │         附加: MarketRegime状态缓存 + 仓位超限减仓单
  │         V4.1新增区块: 实盘偏差监控(M1) + 条件单执行归因(M2) +
  │                       滑点归因(P3) + 预警闭环统计(M3) + 系统健康度(E3)
  │         （全部try/except静默降级，数据不足时自动隐藏）
  │         邮件: [综合分析报告] N只标的 技术面+条件单
  │
19:00 ──── 条件单提醒（scheduler.run_morning_reminder）
  │         内容: 持仓止损/止盈条件单 + 买入推荐条件单 + 新闻风险扫描
  │         邮件: [条件单] 东方财富智能条件单 - 日期
  │
```

### 3.2 周末时间线

```
周六 10:00 ── 周度回顾（scheduler.run_weekly_portfolio）
  │            内容: 本周绩效 + 归因分析 + 压力测试 + 下周建议
  │            邮件: [周度回顾] 日期 | 周收益+x.x%
  │
周六 11:00 ── ML模型训练（scheduler._run_weekly_ml_training）
  │            内容: 全市场XGBoost模型训练 + 交叉验证
  │
周日 10:00 ── 股票池更新提醒
  │
每月1日 09:00 ── Walk-Forward验证（scheduler._run_monthly_walk_forward）
  │               内容: 60天训练/20天验证滚动窗口，检测过拟合
  │               附加: 重置 monthly_start_capital 月度回撤基准
  │               V4.1(P4): 邮件附Deflated Sharpe检验（DSR>0.95才认为夏普显著）
  │               V4.1(E2): 邮件附overfit_guard过拟合守卫审计摘要
  │
每日 10:00 ── 月度策略综合分析检查（scheduler._run_monthly_strategy_analysis，V4.1 E1）
                 仅每月1日实际执行；开关STRATEGY_ANALYSIS_MONTHLY_ENABLED默认关
                 （全量回测耗时长，需人工确认资源占用后在config_local启用）
```

### 3.3 盘中预警联动

```
IntradayMonitor(09:30-15:00)
  │
  ├── 检测到急跌>3% ──→ 设置 systemic_risk 标记
  │                       └── 风控引擎: 总仓位上限强制降至30%
  │
  ├── 检测到盘中暂停信号 ──→ 设置 intraday_pause 标记
  │                          └── 风控引擎: 拒绝所有新买入
  │
  └── 15:30 ──→ 自动过期清除所有盘中风险标记
```

## 四、外部数据源

| 数据源 | 用途 | Python库 | 特点 |
|--------|------|----------|------|
| baostock | 主数据源：历史日线K线 | `baostock>=0.8.8` | 免费，前复权，稳定 |
| akshare | 备用数据源+板块数据 | `akshare>=1.10.0` | 东方财富接口，板块资金流 |
| 东方财富 | 实时行情+条件单格式 | 内置HTTP请求 | 条件单直接对接券商APP |

### 数据获取流程

```python
# data/data_loader.py 中的优先级逻辑:
1. load_daily_data() 优先从进程内 LRU 缓存读取（同session零IO）
2. 缓存未命中时从本地SQLite(stock_db.db)读取
3. SQLite不足时从baostock拉取增量数据
4. baostock失败时回退到akshare
5. V6.0 P2-4: akshare也失败时回退到本地数据库兜底（避免网络故障时完全无数据）
6. 所有数据统一为 pandas DataFrame 格式
```

> **本系统应用**：`data/data_loader.py` 维护一个本地SQLite数据库（`data/stock_db.db`），避免重复拉取历史数据。每日盘后15:30的 `run_daily_task()` 会调用 `skip_update=False` 触发增量更新。

配置采用**分层架构**，敏感信息不进入版本控制：

| 文件 | 作用 | Git跟踪 |
|------|------|----------|
| `config.py` | 公共默认值 + 参数占位符 | ✅ 是 |

| `.env` | 环境变量备选（可选） | ❌ 否(.gitignore) |

加载顺序：`config.py` 默认值 → `from config_local import *` 覆盖 → `.env` 环境变量

| 配置段 | 内容 | 示例 |
|--------|------|------|
| 资金配置 | 总资金、可用现金、现金保留比例 | `TOTAL_CAPITAL = 714_324.76` |

| 操盘密码 | DK信号、生命线、资金监控参数 | `CAOPAN_CONFIG` |
| 纪律配置 | 交易硬约束（基于真实委托验证） | `DISCIPLINE_CONFIG` |

## 常见疑问FAQ

**Q1：系统会自动帮我买卖股票吗？**

A：**不会**（默认情况下）。本系统是"辅助决策系统"，不是自动交易系统：
- 系统告诉你"买什么、买多少、什么价买、止损设哪里"
- 你自己登录券商 APP（东方财富）挂条件单
- 可选：如果配置了QMT（xtquant），可以实现自动执行，但默认关闭

**Q2：系统挂了怎么办？会不会影响我的股票？**

A：完全不影响。因为：
- 你的股票在券商账户里，不在本系统里
- 系统只是"分析师"，不是"经纪人"，它不持有你的股票
- 系统挂了只是今天不收报告而已，明天重启就恢复
- 已挂的条件单在券商服务器上，与本地系统无关

**Q3：我需要一直开着电脑吗？**

A：取决于你想用哪些功能：
- 只要盘后报告：每天15:30前开机运行一次即可
- 要盘中预警：需要交易时间内保持运行（09:30-15:00）
- 要全自动：用Windows任务计划程序设置开机自启
- 推荐：用 `auto_scheduler.py` 一键启动，它会自动管理各时段任务

**Q4：为什么用Python而不是其他语言？**

A：Python是量化交易的主流选择：
- 丰富的金融数据库（baostock/akshare/tushare）
- pandas/numpy/scipy提供强大的数据处理能力
- scikit-learn/XGBoost支持机器学习
- 开发效率高，适合快速迭代策略
- 缺点：运行速度比C++/Java慢，但对日线级别的策略完全够用

**Q5：13个模块我都需要了解吗？**

A：不需要。作为用户你只需关注：
- **strategy/**：产生买卖信号的地方（你看到的报告内容来自这里）
- **risk/**：保护你资金安全的地方（17道关卡）
- **notify/**：给你发邮件的地方
- 其他模块是"后台"，自动工作不需要你操心
