## 1. 系统架构总览

### 1.1 系统定位

高胜率A股交易辅助决策系统（非自动交易），面向个人量化交易者。

- **交易周期**: 中线波段（3天-4周）
- **核心方法**: 条件单驱动 + 纪律自动化
- **数据源**: baostock（历史K线）+ 腾讯行情API（实时价格）+ akshare（备用）
- **输出**: 邮件报告 + 条件单Excel + QMT自动执行

### 1.2 模块架构（13层）

| 序号 | 模块 | 职责 | 核心文件 | 上游依赖 | 下游输出 |
|------|------|------|----------|----------|----------|
| 1 | data/ | 行情数据获取与存储 | data_loader.py, realtime.py | baostock/腾讯API | strategy, backtest |
| 2 | strategy/ | 交易策略与信号生成 | trend_strategy.py, stock_screener.py | data | risk, notify |
| 3 | risk/ | 风控熔断与仓位约束 | risk_control.py | strategy | execution |
| 4 | backtest/ | 策略回测与验证 | engine.py, walk_forward.py | data, strategy | 报告 |
| 5 | factors/ | 多因子计算 | momentum.py, technical.py, volume.py | data | strategy, quant |
| 6 | position/ | 仓位管理 | kelly.py, risk_parity.py, vol_target.py | risk, factors | execution |
| 7 | quant/ | 量化引擎与组合优化 | engine.py, portfolio.py | factors, position | backtest |
| 8 | ml/ | 机器学习信号增强(LightGBM) | trainer.py, predictor.py, features.py | factors, data | strategy |
| 9 | execution/ | 交易执行 | twap.py, slippage_tracker.py | risk, position | broker(QMT) |
| 10 | monitor/ | 盘中实时监控 | intraday_monitor.py | data(realtime) | notify |
| 11 | attribution/ | 绩效归因 | alpha_beta.py, barra.py | backtest | 报告 |
| 12 | notify/ | 通知推送 | email_notify.py, wechat_notify.py | 所有模块 | 用户 |
| 13 | paper_trading/ | 模拟交易验证 | simulator.py | strategy, risk | attribution |

### 1.3 数据流向

```
[baostock] --+
             +--> data/ --> SQLite(stock_db.db)
[腾讯API] --+         |
                      v
             factors/ --> strategy/ --> risk/
                  |           |            |
                  v           v            v
             quant/      ml/(确认)   position/
                  |                        |
                  v                        v
             backtest/ <------- execution/ --> [QMT]
                  |
                  v
             attribution/ --> notify/ --> [邮件/微信]

monitor/ <-- data/(realtime) --> notify/(紧急预警)
```

### 1.4 架构特点

- 单向数据流（无循环依赖）
- 模块间通过config.py解耦
- 降级容错（try/except包裹可选模块）
- ML模块可选（enabled=False时完全跳过）

## 2. 策略引擎

### 2.1 趋势策略（MA20/MA60双均线）

**核心逻辑**: T日收盘判定信号 -> T+1开盘执行

**买入条件（全部满足）**:

| 条件 | 具体规则 | 设计意图 |
|------|----------|----------|
| 趋势确认 | MA20斜率>0 且 close>MA20 | 确保中期趋势向上 |
| 回踩买点 | low触及MA20(+-1%) 且 缩量(量<vol_ma20x70%) | 趋势中的低吸机会 |
| 突破买点 | close创20日新高 且 放量(>vol_ma20x1.5) | 动量突破确认 |
| MACD确认 | DIF>DEA（金叉状态） | 动量方向一致 |
| RSI过滤 | RSI(14) < 70 | 排除超买追高 |
| 急涨过滤 | 当日涨幅 < 7% | 避免追涨停板 |
| 市场环境 | BEAR市禁止开仓 | 系统性风险规避 |
| 个股适应 | ATR% >= 1.5% | 排除低波动白马(如茅台) |

**卖出条件（优先级从高到低）**:

| 优先级 | 卖出条件 | 规则 | 说明 |
|--------|----------|------|------|
| 1 | 强制止损 | low < buy_price x (1-stop_pct) | ATR自适应，约束[5%,10%]，盘中low触发 |
| 2 | 放量大跌 | 单日跌>8% 且 量>2倍均量 | 无条件离场（黑天鹅防护） |
| 3 | 阶梯止盈 | 浮盈>=8%卖1/3，>=20%再卖1/3 | 分批锁定利润 |
| 4 | 回落止盈 | 龙头稳健7%/成长赛道6%/高弹性5%（config.DRAWDOWN_STOP），low触发 | 保护底仓利润 |
| 5 | 趋势破位 | close < MA20 且 MA20斜率<0 | 趋势反转确认 |
| 6 | 时间止损 | 持仓>20**交易日**且浮盈<5% | 强制清仓“僵尸持仓”（V7.1新增，V9.0修复为交易日） |

### 2.2 DK买卖点信号（操盘密码）

对标东方财富付费软件"操盘密码"功能：

- **D点（买入）**: 上升趋势中回踩生命线 + 主力买入/散户卖出
- **K点（卖出）**: 下跌趋势中反弹受阻 + 主力卖出/散户买入
- **趋势过滤**: 仅在趋势向上时响应D点

**控盘生命线**: 黄色EMA13 + 紫色EMA34 双均线系统

**四大优势**:
1. 可回测验证（3年日线+真实成本+分信号类型统计）
2. 参数可自定义优化（EMA周期/偏离阈值网格搜索）
3. 可对接风控和交易闭环（信号->RiskGate->仓位->条件单->执行）
4. 可批量选股扫描（全市场一键筛选D点标的）

### 2.3 市场环境自适应（MarketRegimeDetector）

`strategy/market_regime.py` 中的 `MarketRegimeDetector.detect()` 基于沪深300指数判断大盘状态：

| 环境 | 判定条件 | 策略调整 | 仓位上限(POSITION_MAP) |
|------|----------|----------|------|
| BULL | close > MA20 且 MA20 > MA60 | 正常交易，止盈放宽 | max=0.90 |
| RANGE | 其他情况 | 正常交易，标准参数 | max=0.60 |
| BEAR | close < MA60 且 MA20 < MA60 | 禁止开仓，止损收紧x0.75 | max=0.30 |

**联动机制**：scheduler每日16:15调用 `_cache_market_regime_state()` 将检测结果缓存至 `output/market_regime_state.json`，风控引擎关卡0.9读取该缓存动态调整仓位上限（缓存超过2天则失效回退1.0）。

### 2.4 ATR自适应止损

**公式**: stop_pct = ATR(14) / buy_price x multiplier

**约束**: max(5%, min(10%, stop_pct))

**市场环境调整**: BEAR市 multiplier x 0.75（收紧止损）

**设计原理**: 高波动股(比亚迪ATR%约4%)获得宽止损(~10%)，低波动股(招商银行ATR%约1.5%)获得紧止损(~5%)

**config.py实际参数**:
- `ATR_PERIOD = 14`
- `atr_stop_multiplier = 2.0`
- `trailing_atr_multiplier = 1.5`
- `INITIAL_STOP_LOSS_PCT = 0.10`（10%固定兜底）

## 3. 选股体系

### 3.1 CANSLIM多因子评分（0-100分）

基于William O'Neil经典CANSLIM方法论 + A股实战适配：

| 因子 | 权重 | 量化对应 | 数据来源 |
|------|------|----------|----------|
| C（当期业绩） | 20分 | 单季度扣非净利润同比增速>25% | 基本面配置 |
| A（年度业绩） | 含在C/A/I | 近3年净利润复合增速>20% | 基本面配置 |
| N（新事物） | 20分 | 股价创近60日新高、突破形态 | 技术面打分 |
| S（供给需求） | 20分 | 缩量回踩MA20、放量突破 | 技术面打分 |
| L（领涨龙头） | 20分 | RPS相对强弱、行业内涨幅排名 | 技术面打分 |
| I（机构认同） | 含在C/A/I | 北向资金/机构持仓 | 基本面配置 |
| M（大盘方向） | 20分 | 大盘处于上升趋势 | 指数趋势判断 |

**买入信号加分**:
- 缩量回踩20日均线（经典买点）-> 额外+10分
- 放量突破60日新高（启动信号）-> 额外+10分

### 3.2 硬性筛选层

| 筛选条件 | 参数值 | 说明 |
|----------|--------|------|
| 成交额 | >= 5亿 | V2.4从8亿降至5亿 |
| 均线排列 | 多头排列(close>MA20>MA60) | TREND_MA_BULLISH_REQUIRED=True |
| ST/退市 | 排除 | 含DELISTED_STOCKS黑名单 |
| 股价区间 | 3-300元 | 排除低价垃圾股和高价股 |
| 最低盈亏比 | 2.5:1 | MIN_RISK_REWARD_RATIO=2.5 |

### 3.3 行业配额与输出

- **单赛道配额**: 最多3只（仅对"推荐买入"级别生效）
- **固定输出**: 10只（V2.4取消min_score硬性截断，按评分降序取前10）
- **买入推荐分界线**: min_buy_score=50分（>=50标记"推荐买入"，<50标记"仅观察"）
- **冷却期**: 2天（同一标的短期内不重复推荐）

### 3.4 三步选股流程

1. **大盘方向判断（M因子）** -> 决定是否操作
2. **CANSLIM多因子打分** -> 筛选核心股票池
3. **计算买点/止损/分批建仓方案** -> 输出操作计划

**分批建仓**:
- 第一批 40% 试仓（买点附近）
- 浮盈>=3% 再加第二批 60%（确认趋势）

## 4. 风控体系

### 4.1 三级仓位硬限制

| 层级 | 限制 | 参数 |
|------|------|------|
| 单只ETF | <=20% | etf_max_ratio=0.20 |
| 单只个股 | <=15% | stock_max_ratio=0.15 |
| 单一赛道 | <=40% | sector_max_ratio=0.40 |
| 最低现金 | >=10% | min_cash_ratio=0.10 |
| 持仓数量 | <=7只 | MAX_HOLDINGS=7 |

### 4.2 总仓位动态上限（双层约束）

**第一层：指数均线绑定**（关卡4）

| 市场状态 | 总仓位上限 | 参数 |
|----------|------------|------|
| 指数在MA20上方 | <=80% | total_above_ma20=0.80 |
| 指数跌破MA20 | <=50% | total_below_ma20=0.50 |
| 指数跌破MA60 | <=30% | total_below_ma60=0.30 |

**第二层：MarketRegime动态仓位上限**（关卡0.9，V7.1新增）

| 大盘状态 | 仓位上限 | 来源 |
|----------|----------|------|
| BULL | 90% | market_regime_state.json缓存 |
| RANGE | 60% | MarketRegimeDetector.detect() |
| BEAR | 30% | scheduler每日16:15更新 |

> 两层取最小值生效。缓存超过2天未更新则回退1.0（不约束）。

### 4.3 账户亏损熔断

| 层级 | 触发条件 | 动作 |
|------|----------|------|
| 日度L1 | 单日亏损>=2% | 当日禁止新开仓 |
| 日度L2 | 单日亏损>=3% | 清非主线弱势仓，仓位<=60% |
| 周度 | 单周亏损>=8% | 全仓降至30%以下，暂停3天 |
| 连亏 | 连续3笔亏损 | 暂停开仓3天 |
| 个股渐进 | 同股3/5/6连亏 | 暂停20天/60天/永久禁止 |

### 4.4 策略失效检测器（StrategyFailureDetector）

`risk/risk_control.py` 中的 `StrategyFailureDetector` 基于滚动窗口胜率/期望收益的三级熔断：

| 级别 | 触发条件 | 动作 | position_scale |
|------|----------|------|------|
| 降级(DEGRADE) | 滚动20笔胜率<40% | 仓位减半 | 0.5 |
| 暂停(PAUSE) | 滚动20笔胜率<30% | 禁止买入 | 0.0 |
| 熔断(BREAKER) | 滚动20笔期望<0% | 全面暂停 | 0.0 |

**联动机制**：
- 风控关卡-0.5：读取 `get_status()["position_scale"]`，degrade时强制缩股至50%
- `PositionSizer`：计算仓位时乘以 strategy_scale 缩放因子
- 恢复后前5笔仓位减半（试探性恢复）
- 状态持久化至 `output/strategy_failure_state.json`

### 4.5 月度回撤硬限制（关卡6.5，V7.1新增）

| 参数 | 值 | 说明 |
|------|------|------|
| monthly_drawdown_limit | 5% | 当月累计亏损达5%时禁止新开仓 |

触发后拒绝所有买入，直到次月1日 `monthly_start_capital` 重置。

### 4.6 单笔风险预算硬钳位（关卡14强化，V7.1）

- **约束**: 单笔交易最大亏损 ≤ 2%总本金（`max_risk_per_trade=0.02`）
- **实现**: 关卡14盈亏比检查后，若 `shares x (price - stop_loss) > capital x 2%`，强制缩股至安全手数
- **PositionSizer联动**: `position_sizing.py` 中同样执行 2%硬上限钳位

### 4.7 渐进加仓恢复（RiskStateManager，V7.1新增）

风控触发降仓后，通过 `get_recovery_position_cap()` 分三档恢复：

| 阶段 | 条件 | 仓位上限 |
|------|------|----------|
| 第1档 | 触发后初始 | 30% |
| 第2档 | 本月盈亏持平 | 45% |
| 第3档 | 本月盈利>2% | 60% |
| 解除 | 本月盈利>5% | 100%（不约束） |

关卡0.8读取该状态，超限则缩股或拦截。

### 4.8 反洗盘保护（V7.1）

盘中监控(intraday_monitor.py)中的反洗盘机制：

- **放量急跌检测**: 短时间内大幅下跌但量能异常放大 -> 可能是洗盘而非真正破位
- **V反保护**: 急跌后快速收回 -> 不触发止损
- **缓冲期确认**: 止损触发后等待N分钟确认，避免瞬间插针误触发

### 4.9 浮亏加仓拦截

`block_add_on_loss = True`: 浮亏>0时绝对禁止加仓（铁律，无例外）

### 4.10 交易行为管控

| 规则 | 参数 | 说明 |
|------|------|------|
| 单日开仓上限 | max_daily_opens=2 | 防止频繁交易 |
| 卖出后冷却 | cooldown_after_sell=3天 | 防止情绪化回买 |
| 浮亏加仓 | 绝对禁止 | block_add_on_loss=True |

## 5. 盘中预警体系

### 5.1 V2.6五大检测维度

| 维度 | 触发条件 | 输出 |
|------|----------|------|
| 准涨停股 | 涨幅>=7% + 量比>=1.5 + 成交额>=3亿 | 封板概率(0-95%) |
| 放量突破启动 | 涨幅3-7% + 量比>=2 + 成交额>=2亿 | 突破强度(0-100) |
| 板块联动 | 同板块>=2只涨停 + 跟涨候选涨幅5-9% | 联动预警 |
| 涨停基因联动 | 昨日涨停 + 今日高开>3% + 量比>2 | 连板启动信号 |
| 选股引擎联动 | 赛道候选池 + 涨幅>2% + 量比>1.5 + 成交额>2亿 | 盘中推荐 |

### 5.2 扫描频率与推送

- **扫描间隔**: 10分钟（V2.6从30分钟缩短）
- **覆盖时段**: 09:40-14:50（跳过11:30-13:00午休）
- **首次触发**: 同一标的当日首次满足条件时立即推送，后续不重复
- **推送通道**: 邮件（QQ SMTP）+ 控制台输出

### 5.3 持仓深度预警（alert_engine.py）

- **频率**: 盘中每3分钟单次检查
- **规则**: 9大规则（DK信号/生命线/乖离率/资金流出/止损/涨跌停/筹码/趋势降级/均线死叉）
- **紧急度评分**: 0-100分
- **冷却**: 同一标的15分钟内不重复推送

### 5.4 涨停基因跟踪（zt_gene_tracker.py）

- **触发时间**: 每日09:26（竞价结束后）
- **逻辑**: 获取昨日涨停池 -> 检查今日高开放量情况 -> 识别连板候选
- **连板条件**: 高开>=3% + 量比>=2

### 5.5 降级策略

所有模块遵循"静默降级"原则：
- akshare调用失败 -> logger.warning + 返回空结果
- 网络超时 -> 重试2次后降级
- 非交易时间 -> 跳过执行
- 涨停基因/选股引擎联动失败 -> 不影响其他检测维度

## 6. 条件单与执行

### 6.1 条件单四大类型

| 类型 | 触发条件 | 优先级 | 有效期 |
|------|----------|--------|--------|
| 止损单 | 触发价 = 止损价（ATR自适应） | 三星必挂 | 20天 |
| 止盈单(减仓) | 触发价 = 第一目标价，卖出50% | 二星建议 | 15天 |
| 止盈单(清仓) | 触发价 = 第二目标价，全部清仓 | 一星可选 | 20天 |
| 回落卖出 | 日高回落至触发价 | 二星建议 | 10天 |

### 6.2 止盈目标计算

- **第一目标**: 最近压力位（若有）> 布林上轨（若有）> ATR推算(+2ATR)
- **第二目标**: 次压力位 > +3.5ATR > 固定+15%

### 6.3 操作建议生成逻辑

| 条件 | 建议 |
|------|------|
| composite>=70 且 盈亏>=0 | 继续持有 |
| composite>=55 且 盈亏>=5% | 持有+部分止盈 |
| composite>=45 且 盈亏>-5% | 谨慎持有 |
| composite<30 或 盈亏<=-15% | 建议止损 |
| 浮盈>15%（特殊规则） | 止盈减仓（强制提示锁利） |

### 6.4 执行约束

- **T+1**: T日买入 -> T+1日最早可卖出
- **滑点模型**: 龙头0.2% | 弹性0.5%
- **涨跌停处理**: 一字涨停无法买入(信号作废)，一字跌停每日尝试卖出直至成交
- **输出格式**: 东方财富条件单Excel（openpyxl生成）

## 7. 回测体系

### 7.1 回测参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 回测区间 | 2023-01-01 ~ 2026-07-25 | 3.5年覆盖牛熊 |
| 标的数量 | 10只（等权）/ 74只（全量） | 覆盖8大行业 |

## 8. 量化指标大白话解读

### 8.1 ATR（平均真实波幅）

**定义**: Average True Range，衡量一只股票在一段时间内每天"蹦跶"的平均幅度。

**计算公式（简化）**: ATR(14) = 过去14天每天"最高-最低"幅度的平均值（考虑跳空缺口）

**大白话解读**: ATR就像测量一只股票每天"蹦跶"的幅度。比如招商银行ATR约0.6元，意味着它每天上下波动大约6毛钱；而比亚迪ATR约8元，意味着它每天能蹦跶8块钱。ATR=2元的股票，你设止损时至少要给它2块钱的"活动空间"，否则一个正常波动就把你震出去了。

- **ATR高了**: 说明这股票脾气暴躁，每天大起大落（如比亚迪、隆基绿能）。止损要设宽一点，仓位要小一点。
- **ATR低了**: 说明这股票性格温和，波动小（如招商银行、工商银行）。止损可以紧一点，仓位可以大一点。
- **实操**: 本系统用 ATR x 2 作为止损距离，约束在5%-10%之间。招商银行ATR%约1.5% -> 止损约5%；比亚迪ATR%约4% -> 止损约10%。

### 8.2 布林带（BOLL）

**定义**: Bollinger Bands，由中轨（20日均线）+ 上轨（中轨+2倍标准差）+ 下轨（中轨-2倍标准差）组成的"通道"。

**计算公式（简化）**: 中轨=MA20, 上轨=MA20+2xSTD(20), 下轨=MA20-2xSTD(20)

**大白话解读**: 布林带就像给股票画了一条"高速公路"。中轨是路中心，上轨和下轨是路两边。正常情况下车（股价）应该在路里面跑。如果车撞到上路边（触及上轨），说明跑太快了可能要歇歇；如果车撞到下路边（触及下轨），说明超跌了可能要反弹。

- **带宽收窄**: 说明股票最近很"安静"，波动小，往往是大行情来临前的蓄力（如招商银行横盘时布林带很窄）。
- **带宽张开**: 说明股票开始"发疯"了，大行情正在展开。
- **实操**: 本系统用布林上轨作为止盈目标参考之一（config: BOLL_PERIOD=20, BOLL_STD=2）。股价突破上轨时可作为突破买点确认。

### 8.3 量比

**定义**: 当天每分钟平均成交量 / 过去5天每分钟平均成交量。反映"今天比平时热闹了多少倍"。

**计算公式（简化）**: 量比 = 当日实时成交量 / (过去5日同期平均成交量)

**大白话解读**: 量比就像餐厅的上座率对比。如果一家餐厅平时中午坐50桌，今天突然坐了150桌，量比就是3——说明今天有"大事"（可能是菜降价了/网红推荐了）。股票也一样，量比>2说明今天资金关注度是平时的2倍以上，有"大资金"在动作。

- **量比>2**: 资金高度关注，可能有主力进场（本系统突破检测要求量比>=2）
- **量比>3**: 极度活跃，封板概率大增
- **量比<0.5**: 极度冷清，无人问津
- **实操**: 盘中预警中，准涨停要求量比>=1.5，放量突破要求量比>=2.0。量比是判断"这次上涨有没有真金白银支撑"的核心指标。

### 8.4 换手率

**定义**: 当天成交量 / 流通股本 x 100%。反映"今天有多少比例的筹码换了主人"。

**计算公式（简化）**: 换手率 = 当日成交量(股) / 流通股本(股) x 100%

**大白话解读**: 换手率就像一个教室里"换了多少人"。如果100个座位今天换了3个人，换手率3%——正常。如果换了15个人，换手率15%——说明有大事发生（可能是考试太难跑了一批，或者老师换了来了一批新的）。

- **换手率3-10%**: 健康活跃区间（本系统封板概率模型给满分）
- **换手率<1%**: 无人问津（如工商银行日常）
- **换手率>15%**: 过度换手，可能是主力出货（本系统给低分0.05）
- **实操**: 选股时偏好3-10%换手率的标的，说明有人气但不过热。

### 8.5 乖离率（BIAS）

**定义**: 股价偏离均线的百分比。反映"股价跑离均线有多远"。

**计算公式（简化）**: BIAS = (收盘价 - MA_N) / MA_N x 100%

**大白话解读**: 乖离率就像遛狗时狗离主人的距离。均线是"主人"（慢悠悠走），股价是"狗"（到处跑）。狗跑太远（乖离率过大）必然会跑回来。招商银行如果乖离率+8%，说明它短期涨太猛了，像狗跑出去8米远，大概率要回来歇歇。

- **乖离率>+8%**: 短期超买，回调风险大（alert_engine中触发"乖离率预警"）
- **乖离率<-8%**: 短期超跌，反弹机会
- **乖离率0附近**: 股价贴着均线走，趋势健康
- **实操**: alert_engine的9大规则之一就是乖离率检测，超过阈值会触发持仓预警。

### 8.6 MACD / DK信号

**定义**: MACD由DIF（快线）和DEA（慢线）组成，金叉(DIF上穿DEA)为买入信号，死叉为卖出信号。DK信号是本系统基于MACD衍生的操盘密码买卖点。

**计算公式（简化）**: DIF=EMA12-EMA26, DEA=EMA(DIF,9), MACD柱=2x(DIF-DEA)

**大白话解读**: MACD就像判断一个人"是在加速还是在减速"。DIF是"当前速度"，DEA是"平均速度"。当当前速度超过平均速度（金叉），说明在加速——可以上车。当当前速度低于平均速度（死叉），说明在减速——该下车了。DK信号更进一步：D点=加速+主力在买（双重确认），K点=减速+主力在卖。

- **DIF>DEA（金叉）**: 动量向上，本系统买入条件之一
- **DIF<DEA（死叉）**: 动量向下，alert_engine触发"均线死叉预警"
- **实操**: 买入时必须DIF>DEA；持仓中如果死叉，会触发趋势降级预警。

### 8.7 夏普比率（Sharpe Ratio）

**定义**: 每承担一单位风险获得的超额收益。衡量"性价比"。

**计算公式（简化）**: Sharpe = (年化收益 - 无风险利率) / 年化波动率

**大白话解读**: 夏普比率就像"每挨一巴掌能赚多少钱"。如果两个策略都赚20%，但A策略每天大起大落（波动30%），B策略稳稳当当（波动10%），那B的夏普比率是A的3倍——你"挨打少、赚钱一样多"。夏普>1算不错，>2很优秀。

- **夏普>2**: 优秀（风险调整收益高）
- **夏普1-2**: 良好
- **夏普<1**: 一般（承担的风险不太值得）
- **实操**: 本系统V5.3回测中，Calmar比率1.69（年化13.5%/回撤8%），属于优秀水平。

### 8.8 最大回撤（Max Drawdown）

**定义**: 从历史最高点到最低点的最大跌幅。衡量"最倒霉的时候亏多少"。

**计算公式（简化）**: MaxDD = (谷底价格 - 峰值价格) / 峰值价格 x 100%

**大白话解读**: 最大回撤就像"你最多曾经从山顶摔下来多深"。如果你100万炒到150万，然后跌到138万，回撤就是(138-150)/150=-8%。本系统V5.3最大回撤-8%，意思是"最倒霉的时候，从最高点往下亏8%"。

- **回撤<10%**: 优秀（本系统V5.3为-8%）
- **回撤10-20%**: 可接受
- **回撤>30%**: 风险过大，需要收紧风控
- **实操**: 本系统周度熔断线=单周亏损8%，就是为了防止回撤扩大。

### 8.9 Kelly仓位（凯利公式）

**定义**: 根据胜率和盈亏比计算最优下注比例。

**计算公式（简化）**: f = (p x b - q) / b，其中p=胜率, q=1-p, b=盈亏比。本系统用Half-Kelly: f/2

**大白话解读**: Kelly公式就像"根据赢面大小决定押多少"。如果你玩一个游戏，赢的概率60%，赢了赚2块，输了亏1块（盈亏比2:1），Kelly说你该押40%的钱。但实际中我们只用一半（Half-Kelly=20%），因为"万一连续输几把，全押就破产了"。

- **Kelly值高(>30%)**: 说明策略优势大，可以多配
- **Kelly值低(<10%)**: 说明优势不大，轻仓试探
- **实操**: 本系统默认Half-Kelly，平衡收益与破产风险。配合ATR仓位法: shares = 资金x2% / (ATRx2)

### 8.10 风险平价（Risk Parity）

**定义**: 按各标的波动率的倒数分配权重，让每只股票"贡献相同的风险"。

**计算公式（简化）**: 权重_i = (1/波动率_i) / sum(1/波动率_j)

**大白话解读**: 风险平价就像"分蛋糕时让每个人吃到的'辣度'一样"。如果招商银行波动小（微辣），比亚迪波动大（超辣），那风险平价会给你多分招商银行、少分比亚迪——让每只股票"辣到你"的程度相同。

- **适用场景**: 多标的组合配置时，避免某只高波动股"绑架"整个组合风险
- **实操**: 本系统position/模块中risk_parity.py实现，作为仓位管理方法之一。

### 8.11 VWAP（成交量加权平均价）

**定义**: Volume Weighted Average Price，按成交量加权的平均成交价格。

**计算公式（简化）**: VWAP = sum(价格_i x 成交量_i) / sum(成交量_i)

**大白话解读**: VWAP就像"今天所有买家的平均买入成本"。如果一只股票今天VWAP是50元，说明今天买它的人平均花了50块。如果现在股价52元（在VWAP上方），说明今天买的人都在赚钱——市场情绪偏多。

- **股价>VWAP**: 多方占优，今天买的人都赚了
- **股价<VWAP**: 空方占优，今天买的人都被套了
- **实操**: execution/模块中TWAP算法参考VWAP进行智能拆单，减少大单冲击。

### 8.12 封板概率

**定义**: 本系统自研的量化估算模型，预测一只准涨停股（涨幅>7%）最终封住涨停板的概率。

**计算公式（简化）**: 概率 = 涨幅因子(0-0.4) + 量比因子(0-0.3) + 换手率因子(0-0.2) + 成交额因子(0-0.1)

**大白话解读**: 封板概率就像"判断一个快要烧开的水壶能不能真正烧开"。涨幅9.5%（水已经95度了）+量比3（火很大）+换手率5%（水在翻滚）+成交额10亿（锅够大）= 大概率能烧开（封住涨停）。

| 因子 | 满分条件 | 得分 |
|------|----------|------|
| 涨幅 | >=9.5% | 0.4 |
| 量比 | >=3.0 | 0.3 |
| 换手率 | 3-15% | 0.2 |
| 成交额 | >=10亿 | 0.1 |

- **概率>=70%**: 高级别(H)，大概率封板
- **概率<70%**: 中级别(M)，可能冲板失败
- **实操**: 盘中预警邮件中显示封板概率，辅助判断是否追涨。

## 9. 每日操作工作流（SOP闭环）

### 9.1 每日闭环流程

```
收盘后 ──→ update_holdings.py 更新持仓
  │
16:15 ──→ 综合分析报告（含MarketRegime缓存）
  │
19:00前 ──→ 根据报告在券商APP设条件单
  │
次日 ──→ 执行条件单 / 手动操作
  │
确认成交 ──→ update_holdings.py 更新持仓 ──→ 循环
```

### 9.2 update_holdings.py 持仓管理工具

根目录 `update_holdings.py` 提供CLI持仓更新：

| 模式 | 命令 | 说明 |
|------|------|------|
| 交互式 | `python update_holdings.py` | 逐步引导输入 |
| 命令行 | `python update_holdings.py --code 600519 --name 贵州茅台 --shares 100 --cost 1800` | 一步到位 |
| 单只删除 | `python update_holdings.py --remove 600519` | 移除某只持仓 |
| 清空 | `python update_holdings.py --clear` | 清仓后重置 |

数据写入根目录 `holdings.json`，被报告生成/风控引擎/仓位分析等模块消费。
